# Manual order email setup

Checkout submits order requests to `/api/orders/submit`. Requests remain awaiting payment; staff contact the customer to arrange payment. The store recipient is fixed to **info@purehealthpeptidesshop.com**. A second email confirms the request to the customer.

1. Apply `supabase/migrations/202610070001_manual_orders.sql` in a transaction. It is self-contained and does not require the Stripe or WooCommerce migrations. Only the server service role can read requests and email jobs.
2. Configure server secrets: `SITE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, optionally `ORDER_EMAIL_FROM` (defaults to `orders@purehealthpeptidesshop.com`), `TURNSTILE_SECRET_KEY`, `CRON_SECRET` (32+ characters, required for protected retries), optionally `MONITORING_WEBHOOK_URL`. Set the existing browser Supabase and Turnstile configuration. Never expose the Resend API key through VITE variables.
3. Verify the sending domain in Resend and check that the API key has sending permission for it. Keep Zoho receiving records unchanged. Configure Turnstile for the production hostname.
4. Emails are attempted during order submission. Vercel Hobby runs the backup `/api/cron/process-order-emails` job daily; failed sends may wait until that backup runs. Each backup processes up to 20 pairs of jobs within a bounded execution time. For faster retries, configure an authenticated external scheduler each minute or a plan supporting minute-level cron. Netlify uses the included `scheduled-order-emails` scheduled function each minute. Do not enable ordering without a functioning scheduler.
5. Deploy and submit a test order using a customer mailbox you control. Verify both actual inboxes, product details, address, phone, totals, and pending-payment language. Provider acceptance alone does not establish inbox delivery.

The outbox claims two jobs per invocation using row locks and a five-minute lease, retries failures with exponential backoff, and marks jobs dead after eight failed sends. Monitor pending/processing job age and dead jobs in Supabase. The worker logs delayed/dead-job counts without customer details, attempts an email alert to the store for exhausted retries (deduplicated per UTC day), and also reports to the monitoring webhook when configured. Configure that independent webhook to receive alerts even when Resend is unavailable. Investigate dead jobs and reset their status to pending, attempts to zero, and next_attempt_at to now after resolving delivery configuration. Resend uses a stable idempotency key per email job to protect retries within the provider retention window.

Preview receipts from older deployments are not server orders and cannot be recovered automatically. This flow does not reserve stock or fulfill orders; verify availability and payment before shipping. Existing Stripe order records are separate from these manual requests.
